Filtering happens **before** scoring (doc comment at line 812-815: "Best match first, uncapped — capping is the caller's… Filters before scoring: same results, less work."). The helper (line 800):

```ts
const filterCandidatesByNodeTypeIds = (
  candidates: SearchableNode[],
  nodeTypeIds?: string[],
): SearchableNode[] =&gt; {
  if (!nodeTypeIds?.length) return candidates;
  const selected = new Set(nodeTypeIds);
  return candidates.filter((candidate) =&gt; selected.has(candidate.nodeTypeId));
};
```

**`undefined` and `[]` are identical** — both mean "no filter, return everything" (`!nodeTypeIds?.length`). That is why `fromPanelSelectedIds` can safely collapse "all checked" to `[]`.

Empty query is not an empty result: it returns everything sorted by `title.localeCompare` then `nodesFirst` (real nodes before tag candidates), with a synthetic `match: { score: 0, matches: [] }`. Non-empty query uses Obsidian `prepareFuzzySearch` and sorts by `b.match.score - a.match.score || nodesFirst(a, b)`. Results are uncapped.

### 6. Styling that assumes the modal/toolbar context

Things that could bite inside a small popover:

1. **Fixed panel width `w-64`** (16rem / 256px), passed as `panelClassName="w-64"` from `NodeTypeFilterMenu`. `SearchDropdown` also defaults to `w-64`.
2. **`absolute right-0 top-full z-50`** on the panel — it is positioned relative to `SearchDropdown`'s own `relative shrink-0` wrapper, so it requires that wrapper to have room *below and to the left*. Inside another popover it would render clipped or off-edge; there is no flip/collision logic and no portal.
3. **`overflow-hidden` on the panel**, which is why `SEARCH_DROPDOWN_ITEM_FOCUS_RING` uses an *inset* box-shadow: "Keyboard-only ring for div items; inset so the panel's overflow-hidden can't clip it."
4. **`max-h-64 overflow-y-auto` on the type list** (`&lt;div className="max-h-64 overflow-y-auto py-1"&gt;`) — a nested scroll area inside an already-scrolling popover.
5. **Badge overflow**: the trigger's count badge is `absolute -right-1 -top-1`, which overflows the button box. The modal compensates with `px-1 pt-1` on the toolbar row explicitly to stop its own `overflow-hidden` from clipping it — a popover host would need the same padding.
6. **Obsidian-global behaviours tied to the modal**: `app.keymap.pushScope` for Escape (comment: "Obsidian's modal Escape is registered before React exists… only a pushed scope gets it first") and the `activeDocument` capture-phase outside-click handler. Both would fire inside a non-modal popover too, and the Escape scope would swallow Escape from the host popover.
7. `activeDocument.activeElement` is used in two places (SearchDropdown's focus effect, and the Clear-filter button's focus parking, which reaches for `closest("[data-search-dropdown-panel]")` — a selector only `SearchDropdown` emits).
8. **Search-box threshold of 7** is documented as a desktop-only-modal assumption.</result>
