  ## 1. What proof-kit is
  
  The repo's real name is **roam-prototypes** (`README.md` line 1: "# Roam prototypes"; clone URL `https://github.com/DiscourseGraphs/roam-prototypes`). It is a pnpm monorepo of installable **Roam developer-extension prototypes** published to `https://discoursegraphs.com/releases/prototypes/<prototype>/`. "proof-kit" is just the local folder name. Entry points for the repo as a whole: `pnpm create:prototype` (generator at `/Users/trang.doan/Desktop/code/proof-kit/scripts/create-prototype.mjs`) plus agent instructions in `/Users/trang.doan/Desktop/code/proof-kit/AGENTS.md`.
  
  The thing you actually care about is one prototype inside it: **`prototypes/proof-runner`** (~18k lines). Its purpose (`prototypes/proof-runner/package.json`): *"Runs a pull request's proof kit from a Roam page: loads the PR's Discourse Graph build and plays the kit's cases in a panel in the right sidebar."*
  
  Pipeline, input → output:
  
  1. **Input**: a *proof kit* — JSON (on disk) or a `{{proof}}` block tree (on a Roam page) describing one PR's proof. Cases are generated upstream by `qa.ts` from the PR's diff + the Linear ticket's "Done When" bullets.
  2. **Load**: on a kit page the runner reads `pr:: 1506` / `build:: <branch>`, fetches that PR's CI build of the Discourse Graph extension from `discoursegraphs.com/releases/roam/<branch>/`, and verifies the commit against the PR head (`src/roam/build-loader.ts`).
  3. **Gate**: a checklist of needs — runner installed, machine connected, graph setup, build, database session, agent (`src/roam/checklist.ts`, `tests/run-gate.test.ts`).
  4. **Prepare**: fixtures in phases `before-load` / `in-session` / `outside` (`src/core/fixtures.ts`), each with a `check` probe so already-prepared data is skipped.
  5. **Run**: a state machine (`src/core/machine.ts`, 1355 lines) plays each case's steps through an executor — Roam DOM (`src/roam/executor.ts`) or Obsidian over CDP (`obsidian/executor.ts`) — then evaluates `expect`.
  6. **Output**: verdicts, screenshots, `result.md` (a PR comment), `kit-report.md`, `records.json`, `journal.jsonl`, and a `runs::` line written back onto the Roam kit page.
  
  **Platforms: both Roam and Obsidian.** Roam is the primary/original target; Obsidian support is the current (uncommitted) work — see §6.

  ### What counts as an assertion / pass-fail
  
  `/Users/trang.doan/Desktop/code/proof-kit/prototypes/proof-runner/src/roam/words.ts:85-103` is the clearest statement:
  
  ```ts
  // What a person does in a case, if anything: decide it by eye, or do it by hand.
  export type PersonNeed = "judge" | "by-hand";
  
  export const needOf = (item) => {
    if (item.steps.length === 0 && item.intent) return "by-hand";
    if (item.judge && !item.hasCheck) return "judge";
    return null;
  };
  
  export const purposeLine = (item, setup) => {
    ...
    if (need === "by-hand") { ... label: "You'll do this one by hand." }
    if (need === "judge") return { label: "You'll judge:", text: plainText(item.judge ?? "") };
    if (item.checks) return { label: "Passes if", text: plainText(item.checks) };
  ```

  ```ts
  // A bullet holds when every case under it passed.

    if (verdicts.some(v => v === null)) return null;
  ```

  ### Anti-patterns / integrity rules the runner enforces
  
  - **A typo can't silently drop a check.** README `prototypes/proof-runner/README.md`: *"An attribute the parser doesn't know is an error, so a typo can't leave a case without its check."*
  - **A tester-assisted pass is not a clean pass.** `words.ts:354-356`: *"A pass the person gave or helped along: they passed it after a failure, did a step themselves, or fixed one during the run."* Those surface in the PR comment as *"N passed by the tester"*.
  - **Kit bugs are separated from product bugs.** `words.ts:356-358`: *"The cases whose kit needs fixing: the person passed one after a step or a check failed, couldn't test one, or did a step themselves. **A failure the person agreed with is the PR's, not the kit's, so it isn't here.**"*
  - **Skipping requires a written reason.** `bar.ts:1516/1524/1535/1549`: *"Why can't you tell?" / "Why leave this case out?" / "What did you see work?"* — all `required: true`.
  - **An agent may not issue verdicts, and agent-authored JS needs human Allow** (`agent-tools.ts:5-11`, `README.md` "Agent tools").
  - **Never test against production.** `README.md` "What it changes": *"CI builds are compiled against the production database, and tests never run there… the runner points the PR's CI build at the proof database before it runs: it swaps the Supabase URL and key for the proof database's and Discourse Graph's website API for the embeddings stub, and **refuses the build if anything of the hosted stack is left**."*
  - **Secrets never land in a kit.** `src/core/template.ts:1-7`: *"Strings are filled only when they run, so keys never land in a kit, a proposed kit or a generated storyboard on disk."* (`{{env.NAME}}`, `{{kit}}`, `{{run}}`, `{{ns}}` tokens.)
  
  I found **no numeric scoring rubric** anywhere.
