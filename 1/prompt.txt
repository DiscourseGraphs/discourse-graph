Note `eslint-comments/no-restricted-disable` also errors on disabling `obsidianmd/*`, `no-console`, `no-eval`, `@typescript-eslint/no-explicit-any` and others, so a described disable of an `obsidianmd/*` rule will *still* error.
  2. `no-forbidden-elements` for per-user CSS / popout windows has no sanctioned exception. The maintainer-endorsed path is constructable `CSSStyleSheet` (`new CSSStyleSheet()` + `doc.adoptedStyleSheets`), which also works for a popout window's own document. If a `<style>` fallback must stay, expect the finding to persist; issue #197 is the precedent and it ended without relief.
  3. To reproduce review locally, prefer adding `obsidianmd/obsidian-workflows@v1` as a CI job over hand-copying the doc's config snippet — the snippet explicitly does not replicate severities.
