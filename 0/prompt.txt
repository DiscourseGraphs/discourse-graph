HIGH — apps/roam/src/utils/materializeSharedNode.ts:423-427 — the hoisted collision check tests the wrong title

The pre-check is called with validated.title, but both import paths below are called with pageTitle:

title: validated.title,        // line 426, the hoisted pre-check
title: pageTitle,              // lines 456 and 461, updateImportedPage / createImportedPage

pageTitle is the decorated title (materializeSharedNode.ts:372-375):

const pageTitle =
  (sharedNode.coreTitle && nodeType
    ? decorateTitle(nodeType.format, sharedNode.coreTitle)
    : null) ?? validated.title;

Both real callers pass nodeType — importSharedNodes.ts:40 and refreshImportedNode.ts:58, each from nodeTypesBySchemaId.get(sharedNode.schemaId) — and coreTitle is populated from core_title in sharedNodes.ts. So in the ordinary cross-app case the two titles differ, and the check guards a title that is never written.

Two consequences, in opposite directions:

1. The hoist fails at its own purpose. When the decorated title collides but the raw one is free, the pre-check passes, importNodeAssets runs and uploads, and then createImportedPage/updateImportedPage returns title-collision. That is exactly the unrevocable upload for a rejected import that the reordering exists to prevent — and, as the titleCollisionFailure docstring says, it cannot be swept up afterwards.
2. A new false rejection. When the raw title collides but the decorated one is free, the pre-check now aborts an import that previously succeeded, with a message naming a title the import would never have used. This regresses working imports and refreshes.

On the rename branch the same substitution misfires both ways: titleCollisionFailure compares getPageTitleByPageUid(importedPageUid) (which holds the decorated title) against validated.title, so needsRename reads true spuriously, and then getPageUidByPageTitle(validated.title) looks up the wrong page.

Fix is one word: pass title: pageTitle at line 426.
