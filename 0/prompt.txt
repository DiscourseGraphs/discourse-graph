Read-only PostHog analysis: measure Roam extension version adoption for the Discourse Graphs project. Don't create, edit, or delete anything in PostHog (no insights, dashboards, cohorts, or annotations). Only run queries.

## Context
We're about to ship ENG-1955 (Roam canvas relation arrows migrate to a new `discourse-relation` shape type, schema v6). Older extension versions can break on canvases saved by newer ones, and one Roam graph can have several users on different plugin versions. A fallback that lets older clients read the new shape type shipped in Roam extension 0.22.0, released to Roam Depot around 2026-08-24. Question: what share of active installs are on 0.22 or later, and which graphs currently mix versions below 0.22 with 0.22+?

## Telemetry facts
- Roam extension events go to PostHog US (us.i.posthog.com). Find the project that has the `Extension Loaded` event. If several projects have it, pick the one with Roam extension traffic and say which one you used.
- On every load the extension sends `Extension Loaded` with properties `version` (e.g. "0.22.0"), `buildDate`, `buildCommit`, `buildBranch`, `versionStamp`, `extensionInstallId` (a random id stored in the browser's localStorage, so one install = one browser) and `graphName`.
- These properties were added in 0.21.0 (ENG-1940), so installs older than 0.21 don't show up.
- Missing values are sent as "-".

## Steps
1. Load the posthog querying skill (posthog:querying-posthog-data) and confirm you're on the right project.
2. Check property values first: distinct `version` values and distinct `buildBranch` values in the last 30 days, with counts. If `buildBranch` has values other than main (or "-"), dev/preview builds are mixed in: report them and exclude them from the adoption numbers with `properties.buildBranch IN ('main', '-')`, showing the totals with and without that filter.
3. Run these HogQL queries (adapt the syntax if the tool needs it, but keep the logic):

Q1. Share of active installs on 0.22 or later (latest version per install, last 30 days):
WITH latest AS (
  SELECT properties.extensionInstallId AS install,
         argMax(properties.version, timestamp) AS version
  FROM events
  WHERE event = 'Extension Loaded'
    AND timestamp > now() - INTERVAL 30 DAY
    AND properties.extensionInstallId NOT IN ('-', '')
  GROUP BY install
)
SELECT count() AS installs,
       countIf(toInt(splitByChar('.', version)[1]) > 0
            OR toInt(splitByChar('.', version)[2]) >= 22) AS on_0_22_plus,
       round(100 * on_0_22_plus / installs, 1) AS pct_0_22_plus
FROM latest
WHERE version != '-'

Q2. Breakdown by version:
WITH latest AS (
  SELECT properties.extensionInstallId AS install,
         argMax(properties.version, timestamp) AS version
  FROM events
  WHERE event = 'Extension Loaded' AND timestamp > now() - INTERVAL 30 DAY
  GROUP BY install
)
SELECT version, count() AS installs FROM latest GROUP BY version ORDER BY installs DESC

Q3. Graphs with mixed versions right now:
WITH latest AS (
  SELECT properties.extensionInstallId AS install,
         argMax(properties.graphName, timestamp) AS graph,
         argMax(properties.version, timestamp) AS version
  FROM events
  WHERE event = 'Extension Loaded' AND timestamp > now() - INTERVAL 30 DAY
  GROUP BY install
)
SELECT graph,
       groupUniqArray(version) AS versions,
       countIf(toInt(splitByChar('.', version)[2]) < 22) AS installs_below_0_22,
       count() AS installs
FROM latest
WHERE version != '-'
GROUP BY graph
HAVING installs_below_0_22 > 0 AND installs_below_0_22 < installs
ORDER BY installs DESC

4. Also run Q1 with a 7-day window, to see recent adoption.
5. Also count graphs with ANY active install below 0.22, even if no other version is present there: canvases in those graphs could still be opened by an upgraded collaborator later.

## Report back (keep it short)
- Project used, query window(s), and whether you filtered buildBranch.
- Q1 for 30 and 7 days: installs, on 0.22+, percentage.
- Q2 table.
- Q3: the number of mixed-version graphs, and the list (graph name, versions, installs below 0.22 / total). Graph names are fine to show me, but flag it if a name looks like personal data.
- The step 5 count.
- Caveats: installs below 0.21 aren't visible, installs are per browser not per person, and any data quirks you noticed (e.g. unparseable versions).
