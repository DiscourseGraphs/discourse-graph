Schema lookup failure silently drops relations

When the batched schema request fails, schemaMap stays empty and every relation skips import. failed remains zero, so the user sees no relation failure despite losing the entire batch.

Learn more
The batched schema lookup in importRelationsForImportedNodes ignores its error response and fills schemaMap only from data. A request error leaves the map empty; the per-relation guard then skips every otherwise importable relation. The new single post-import pass covers all imported spaces, so one lookup failure hides all their relations while the failure counter stays at zero.

Example: A user imports X from A and Y from B, and the my_concepts schema query fails transiently. Both nodes import, no relations import, and no relation-failure notice appears.

Recommended fix: Check the batched schema query error before looping. Propagate it to the existing import error handling, or count affected relations as failures and show a notice; do not treat a failed query as an empty set of schemas.
