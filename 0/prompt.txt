Here are review findings. 
- apps/roam/src/utils/publishNodesToGroups.ts:378 — medium. The new asset stage only ever inserts/updates FileReference rows; nothing deletes rows for assets a node no longer references. The PK is (source_local_id, space_id, filepath), so removing an image from a node and republishing leaves the old row intact alongside any new one, and an importing destination will pull an asset the published content no longer mentions. The Obsidian path this mirrors does exactly this cleanup (apps/obsidian/src/utils/syncDgNodesToSupabase.ts:754, delete where filepath NOT IN the current set). Same effect if Roam ever rotates a download token, since the token is part of filepath.
- apps/roam/src/utils/publishNodeAssets.ts:45 — medium. Every publish re-fetches every asset of every successfully upserted node: two sequential HTTP round trips per reference (descriptor + bytes), with no check against existing FileReference.last_modified (again, the Obsidian caller does check before calling addFile) and no dedup across nodes. Republishing 100 image-bearing nodes just to add one group means ~200 serial fetches inside handlePublish with the dialog blocked and no progress indication; an image shared by 5 nodes is downloaded 5 times. file_exists prevents the re-upload but not the re-download or re-hash.
- apps/roam/src/utils/copyAssetToSharedStorage.ts:74 — low. When the descriptor reports no size (Firebase omits it, or returns null, which Number(null) === 0 turns into a passing 0), the pre-download guard is bypassed and the full body is buffered into the Roam tab via arrayBuffer() before the cap is applied. A large video attachment with a size-less descriptor is downloaded in full only to be discarded, and can exhaust tab memory. A Content-Length check on the byte response (or an abort on overrun) would keep the guard meaningful.
- apps/roam/src/components/Export.tsx:891 — low. assets.tooLarge / assets.failed hold one entry per reference, not per distinct file, so the toast miscounts: one 10 MB PDF embedded in three published nodes yields "3 files were too large to copy." Deduplicating on sourceRef for the message (the way distinctBytes does for copies) would report 1.
- apps/roam/src/components/Export.tsx:866 — low. The PostHog property assetDistinctByteCount carries assets.distinctBytes, which is a count of distinct content hashes, not bytes. Anyone reading the funnel will interpret "byte count" as volume; assetDistinctBlobCount (or actually summing sizes) matches the value.
