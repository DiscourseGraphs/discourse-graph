Ok, I had pushback on the solution we selected for ENG-1870. There is another way: Have a bucket-neutral URL detection, and follow up with a call to `roamAlphaAPI.file.get`, which returns a File promise. The latter has metadata. There is an assumption that the api endpoint would fail for non-Roam URLs, which I think we should check, not sure how. Disadvantage: We cannot separate the metadata fetch from the data fetch. Advantage: according to the Roam documentation, "Fetch a file hosted on Roam. You could also `fetch` the url yourself, but `get` handles decryption on encrypted graphs and restores the original file name and type metadata." That is decisive for encrypted graphs. That said, firebase documentation does not mention encryption, so it's possible that the encryption does not affect metadata; in which case our metadata-only call may still work. (Also hard to test.)
