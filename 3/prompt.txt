## What it does (sourced)

- **Tests run inside a real Obsidian.** Each test calls `evalInObsidian({callback, input})`. The callback is turned into a string, sent over CDP and run inside Obsidian, where it gets `app`, `obsidianModule`, `lib` and `context`. Anything passed in or returned must be plain JSON; live objects persist between calls through `ContextId`. [writing-tests](https://github.com/mnaoumov/obsidian-integration-testing/blob/main/docs/src/content/docs/guides/writing-tests.md)
- **It launches its own Obsidian by default.** It starts the installed Obsidian binary with a temporary `--user-data-dir` on a free `--remote-debugging-port`, so it never touches your own Obsidian's config, vault list or open window, and runs alongside it (`src/obsidian-instance.ts`). An attach mode (`port: N`) connects to an already-running Obsidian instead. You can pin Obsidian versions, and the window can be moved off-screen. It is not headless. [transports](https://github.com/mnaoumov/obsidian-integration-testing/blob/main/docs/src/content/docs/guides/transports.md)
- **UI interaction and screenshots.** It sends trusted input through Electron's `sendInputEvent`: typing into the editor, key presses, hover, click and `waitUntil`. The docs point out that dispatched DOM events do nothing in Obsidian or CodeMirror. `captureObsidianScreenshot` returns a PNG and can pin its exact size. [user-input](https://github.com/mnaoumov/obsidian-integration-testing/blob/main/docs/src/content/docs/guides/user-input.md)
- **Plugin loading.** Global setup copies the build from `dist/dev` or `dist/build` (hardcoded in `src/global-setup-core.ts`, lines 78–79) into a temporary vault and enables it. It throws `StaleBuildError` if `main.js` is older than `src/`.
- **Runners.** It has global-setup entry points for Vitest and Jest, and requires `fileParallelism: false`. It also exposes `connectToCdp()` plus an `npx obsidian-integration-testing` command for scripts outside a test runner.
- **Dependencies.** `puppeteer-core` and `webdriverio`. Peer dependencies are `obsidian ^1.12.3`, `sharp` and `type-fest`, and it needs Node 22+.
- **Platforms.** Its CI runs a boot test on Ubuntu (under `xvfb-run`, sandbox disabled), macOS and Windows, but only when triggered by hand (`validate-installer-boot.yml`). There is also an Android path via Appium.
- **Maturity.**
  - MIT licence, 3 stars, 0 issues ever filed.
  - Created March 2026; last push 2026-09-21; 117 npm versions, currently 16.0.0; about 3.3k downloads a month.
  - The author, mnaoumov, maintains `obsidian-dev-utils` (108 stars) and about 25 of his own plugins that use this library.
  - Outside consumers include [obsidian-latex-suite](https://github.com/artisticat1/obsidian-latex-suite) (`^10.3.2` with Vitest 4), Vaultman, image-upload-toolkit and paste-mode.

## Fit with our repo (sourced from local files)

- `apps/obsidian` builds to a flat `dist/`, not `dist/dev` or `dist/build`.
- Our `obsidian` dependency is `^1.7.2`, below the `^1.12.3` peer requirement.
- Our Vitest catalog is `^4.0.0`, which matches.
- `sharp` would be a new native dependency.

## Comparison

| | Library | #1327 (raw CDP attach) | #959 (Playwright over CDP) |
|---|---|---|---|
| What it proves | Real app, real vault, trusted input, pinned Obsidian versions | Real app, but whatever vault you have open; input is its own | Real app, test vault, Playwright input |
| Setup cost | Install the package plus peer deps, and adapt the build folder | None (about 150 lines, no deps) | Playwright; rewrites `obsidian.json`; you must quit Obsidian first |
| Agent-friendliness | High: launches and cleans up itself, one command, PNG capture | Medium: needs Obsidian already open on 9222 and a preflight check | Medium: fights with the user's running Obsidian; screenshots only on failure unless extended |
| CI | Yes (xvfb shown in its own workflow) | No (needs an open vault) | Possible, macOS-centric |
| Parallel worktrees | Safe: temp profile and free port per run | Unsafe: shared port 9222 and a shared vault plugin folder | Unsafe: fixed 9222 plus a global `obsidian.json` (the PR admits it) |
| Maintenance risk | Outside dependency with very fast major releases and one maintainer; APIs have broken often | We own it, and it's small | We own it; the Playwright/Electron workaround is fragile |

## Inference (not verified)

- **macOS launch.** The launcher-forking problem that broke #959 likely doesn't apply here. The library talks to Obsidian over a CDP port rather than Playwright's pipe to the process it starts, and its macOS CI job boots Obsidian. Nobody has tried it on our machines yet.
- **Build folder.** A small wrapper can copy `dist/` to `dist/build`. Alternatively, `installPlugin: false` plus `populate` would let us seed the plugin ourselves.
- **Timestamp checks.** The stale-build check compares file timestamps, which may be noisy in a monorepo.
- **Peer dependency.** The `obsidian ^1.12.3` requirement means either bumping our typings or accepting a peer warning.
- **Test style.** Callbacks run as strings inside Obsidian, so they can't import our `src`. Tests poke `app.plugins.plugins["discourse-graphs"]` and the DOM, much like #1327 scenarios do today.

## Recommendation

- **Keep:** `connectToCdp` (owned instance, temp vault, free port), the `lib` input helpers and `captureObsidianScreenshot`. Together they replace #1327's attach-to-9222 setup and #959's `obsidian.json` rewriting.
- **Hold off on:** the Vitest global-setup integration project, until a spike shows it stays stable across a couple of releases.
- **Pin an exact version** (no `^`).
- **Close #959.** Keep #1327's scenario and assertion style as the thin layer on top.
