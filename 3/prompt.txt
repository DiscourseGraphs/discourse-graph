    - The uuid changes on every render.
  - **Uids contain `-` and `_` (seen live):** examples are `-4QT1cn31`, `Gk_jF5rN-`, `s-WzhvpZR`, `65gGXSN_F`. So never parse ids by splitting on `-`.
    - roamjs `getUidsFromId` takes the last 9 characters, which assumes 9-character uids. Uids created through the API with a custom uid can have other lengths (not verified).
  - **Recommended selector:** `el.querySelector('.rm-block[data-block-uid="' + CSS.escape(uid) + '"]')`. It is an exact match with no suffix ambiguity. The fallback is `[id$="-${uid}"]`, which find-replace uses.
  - **Always scope to your own container.** `data-block-uid` is the same in the main window, the sidebar and our preview. In the probe, only our copy existed because the main window showed another page; whenever the main window or sidebar shows the same page, a document-level query would also match those copies.
  
  ### 3. Collapsed blocks
  - **Children of a closed block are not in the DOM at all (measured).** The closed block itself was present with `rm-block--closed`; its child was absent by both id and `data-block-uid`.
  - **Collapse state is the global, synced `:block/open`.** The docs describe `data.block.update({block:{uid, open}})` as "collapse state". The find-replace extension expands by calling `updateBlock({open:true})` on each ancestor, then waits with a MutationObserver for `[id$='<uid>']` (`fbgallet/roam-extension-find-replace` `src/highlighting.js` `expandWholeParentPath`, and `nodeTraversal.js` `openParentNodes`). That approach mutates the user's graph.
  - **`renderBlock "open?": true` forces only the rendered root open, without a DB write (measured).**
    - The root's children appeared and `:block/open` stayed `false` in the DB.
    - A collapsed descendant's children did not appear. In a chain G(closed) → P(closed) → X, rendering G with `open?: true` showed P but not X.
  - **Options to reveal a nested block without mutating data:**
    - (a) Render the target block directly with `renderBlock({uid: target, "zoom-path?": true, "open?": true})`. This was measured to work and shows a breadcrumb (`.rm-zoom-path`), but it does not show the target in the context of the whole page.
    - (b) Render the closest collapsed ancestor with `open?: true`. This only works when exactly one level is collapsed.
    - (c) Temporarily toggle `:block/open` and restore it afterwards. This writes to the DB and syncs to collaborators, so I would avoid it.
  - **Unverified:**
    - Whether clicking the expand arrow inside our preview writes `:block/open` (I didn't test it, to avoid writing). Normal outline toggles do persist.
    - Whether toggling a root that was forced with `open?` writes to the DB.
  - **Embeds and linked references keep their own collapse state, not `:block/open`.**
    - Embeds render with `rm-embed-children--closed`.
    - The changelog says "Block embeds will now be expanded by default".
    - find-replace's code comment: ":block/open doesn't affect blocks in the Linked references section".
  
  ### 4. Lazy rendering
  - **Page outline (measured):** a page with 161 visible blocks rendered all 161 synchronously. The count did not change after 2s or after scrolling to the bottom, and there were no "load more" controls. I saw no virtualization at that size.
  - **Very large pages:** not verified. Every page with more than 2,000 blocks in the test graph was mostly collapsed.
  - **Linked references load lazily** (changelog, June 12, 2023). This is irrelevant if you pass `hide-mentions?: true`.
  - **Re-renders:** Roam re-renders blocks when their data changes (not verified), so don't hold element references for long.
  
  ### 5. Block references and embeds (measured)
  - **Block refs:** `span.rm-block-ref[data-uid="<uid>"]`, rendered as text only. They have no `.rm-block` or `data-block-uid`, so they can't collide with the `.rm-block[data-block-uid]` selector.
  - **Embeds (`{{embed-children:}}`):**
    - Structure: host `.rm-block__input` → `div.rm-embed-container.rm-embed-children__container` → `.rm-embed-children__inner` → `.rm-block-children` → `.rm-block[data-block-uid=<embedded uid>]`.
    - The embedded copies carry the real `data-block-uid`, so a plain selector would match them.
    - Their ids use a different windowId: `block-input-embed-<hostUid>-<embeddedRootUid>-<userId>-<uid>`.
  - **Choosing the real block:** filter with `!node.closest('.rm-embed-container')`, or require `node.closest('.rm-block__input') === null` relative to the root (`.rm-embed-container` sits inside the host's `.rm-block__input`). Take the first remaining match. I verified the `children` variant only; plain `{{embed:}}` is assumed to share `.rm-embed-container`.
  
  ### 6. Edit mode (measured)
  - **Clicking a block** replaces `div.rm-block__input` with `textarea.rm-block-input.rm-block__input--active`. The textarea keeps the same id (`block-input-render-page-...-<uid>`).
    - The old div is gone, so any stored reference to it goes stale.
    - The `.rm-block[data-block-uid]` container survives, so highlight on `.rm-block` or `.rm-block-main`, not on `.rm-block__input`.
  - **`getFocusedBlock()`** returns `window-id: "render-page-<pageUid>-uuid..."`. That window can be targeted with `setBlockFocusAndSelection`.
  - **Editing is live.** The preview is fully editable and writes to the graph, and keyboard focus moves into Roam's editor, so Roam's keyboard shortcuts will act on the preview.
  
  ### 7. Scrolling inside our own container
  - **`scrollIntoView` scrolls every scrollable ancestor**, which can include Roam's main panel or the document. find-replace uses `scrollIntoView({behavior:"smooth", block:"center"})` because it scrolls Roam's own view.
  - **For a preview pane, compute the offset yourself:**
    `container.scrollTo({ top: target.getBoundingClientRect().top - container.getBoundingClientRect().top + container.scrollTop - (container.clientHeight - target.offsetHeight) / 2, behavior: "smooth" })`
    - Do this after `await renderX(...)`, inside an rAF.
    - Call it on the `.rm-block-main` of the matched `.rm-block`, not the whole `.rm-block`, which includes all children.
  - **Unverified:** `scrollIntoView({container: "nearest"})` limits scrolling to the nearest scroller in recent Chromium. I did not check which Chromium version Roam desktop's Electron ships.
  - **Flash highlight:** a class added to Roam-owned nodes may be lost when Roam re-renders that block (not verified). Use a short timeout, or an absolutely positioned overlay inside the container.
